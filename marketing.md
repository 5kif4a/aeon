# Маркетинг: путь до 10 / 100 / 1000 активных пользователей

Стратегия привлечения для aeon. Связана с [monetization.md](monetization.md): экономика
сходится при CAC ≤ $1/MAU, удержании D7 ≥ 30 % и выключенном thinking у Gemini.

**«Активный пользователь» (MAU/WAU)** = задал агенту или Совету хотя бы один вопрос за
последние 7 дней. В данных это строка в `daily_usages` с ненулевым счётчиком.

Воронка, которую меряем с первого дня:

```
источник (start-параметр) → /start → дата рождения указана → 1-й вопрос агенту
                                     → Trial запущен → возврат на 7-й день → Pro
```

Онбординг в боте лёгкий: `/start` сразу показывает главный экран, дата рождения запрашивается
отдельной кнопкой. «Онбординг завершён» = `birth_date` заполнен, потому что без него не
приходят ежедневные и еженедельные сообщения, то есть не работает главный механизм возврата.

## Что уже есть для продвижения

Активы продукта, на которые можно опираться в постах и роликах (все реализованы):

- Три агента с разными характерами и ответы **с цитатами из первоисточников** (глава, страница).
  Это главный аргумент против «очередной GPT-обёртки».
- **Совет трёх**: один вопрос, три взгляда и общий вывод. Самый шеримый формат ответа.
- **Memento Mori календарь**: 4 680 недель жизни в Mini App.
- Ежедневные и еженедельные сообщения от агентов в локальное время, кнопка «сделано» со стриком.
- Бесплатный 7-дневный Trial с RAG и одним Советом, оплата Pro в два тапа через Stars.
- Два языка: RU и EN, включая ответы агентов.

Чего пока нет, и что нужно учесть в планах ниже: `/start` не читает start-параметр, шеринга
ответов и картинки календаря нет, реферальной программы нет.

## Этап 0 → 10: руками (~1 неделя)

Цель не пользователи, а обратная связь и калибровка воронки.

- [ ] 10–20 личных сообщений знакомым из целевой аудитории (саморазвитие, книги, предприниматели).
      Формулировка: не «потести бота», а «выбери агента и задай реальный вопрос, который тебя грызёт».
- [ ] Смотреть на поведение, не на похвалу: указал дату рождения? задал второй вопрос?
      запустил Trial? вернулся после утреннего сообщения?
- [ ] Определить агента-«лицо продукта» (гипотеза: Макиавелли самый острый и шеримый).
      Он пойдёт в заголовки постов и роликов.
- [ ] Проверить, что лимит Free (3 вопроса в день) не убивает первое впечатление: смотреть,
      сколько пользователей упираются в него в первый день и сколько из них жмут «Trial».

## Этап 10 → 100: комьюнити и бесплатные площадки (1–2 месяца)

Бот двуязычный, работаем на два рынка сразу.

**RU:**
- [ ] Посевы у микроканалов (1–10 тыс. подписчиков) в нишах: стоицизм, саморазвитие, книги,
      психология. Бесплатно / бартер / символически.
- [ ] Каталоги ботов (@BotsArchive и аналоги), каталог Telegram Mini Apps.
- [ ] Кейс-статья на vc.ru / Habr: «Как я сделал ИИ-наставника-стоика в Telegram с цитатами
      из „Размышлений"». Технические кейсы стабильно дают первые сотни установок.

**EN:**
- [ ] Reddit: r/Stoicism, r/Jung, r/TelegramBots. Не реклама, а пост-история: «I built a bot to
      talk to Marcus Aurelius, grounded in the actual Meditations, with chapter and page».
- [ ] Product Hunt: разовый всплеск трафика и бэклинки. Готовить после того, как заведены
      start-метки, иначе всплеск нельзя будет отделить от органики.

## Этап 100 → 1000: виральные механики + платные посевы (3–6 месяцев)

### Сначала вшить в продукт (снижает CAC на всё последующее)

- [ ] **Start-параметр источника**: читать `context.args` в `/start`, писать в новую колонку
      `users.acquired_from`. Без этого ни один платный канал нельзя оценить.
- [ ] **Шеримый memento mori**: картинка «твоя жизнь в неделях» с подписью бота и кнопкой
      «поделиться». Самый вирусный формат ниши, люди сами постят его в сторис.
      Данные уже есть (`birth_date`, `life_weeks_lived`), нужна генерация изображения.
- [ ] **Реферальная программа**: `?start=ref_<telegram_id>`. Награда должна быть в текущей
      валюте лимитов: например, +7 дней Trial другу и +5 RAG-ответов пригласившему на день.
      Поле `tokens` для этого не подходит, оно нигде не используется; нужна отдельная механика.
- [ ] **Шеринг ответов агента**: кнопка «переслать» под ответом и под Советом трёх. Каждый
      пересланный ответ = реклама в чужом чате. Совет трёх с тремя подписями особенно хорошо
      выглядит в пересылке.

### Потом платное

- [ ] **Посевы в TG-каналах** (RU: саморазвитие/книги/психология), главный масштабируемый канал.
      Ориентиры: ~$0.1–0.3 за `/start`, при удержании 30–40 % → **$0.3–1.0 за MAU** →
      бюджет до 1000 MAU ≈ **$300–700**. Начинать с 3–5 тестовых каналов по $20–50,
      масштабировать те, где CAC ниже (поэтому нужны start-метки по каналам).
- [ ] **Короткие видео** (TikTok/Reels/Shorts): ниша стоицизма огромна и дешева. Формат:
      скринкаст диалога «спросил у Макиавелли, как поступить с токсичным начальником» или
      Совет трёх на один жизненный вопрос. Один залетевший ролик = сотни установок бесплатно.
- [ ] Telegram Ads только после посевов: порог бюджета выше, таргетинг хуже ручного выбора каналов.

## Сходимость с экономикой

| Параметр | Значение |
|---|---|
| CAC (посевы) | ~$0.3–1.0 за MAU |
| Конверсия MAU → Trial | цель 20 % |
| Конверсия MAU → Pro | ~3 % → ~$15–30 за подписчика |
| Доход с подписчика | ~$3.5 в месяц (Stars, 350 ★) |
| LLM-расход на подписчика | ~$0.4 в месяц при thinking = 0 |
| Окупаемость подписчика | 5–10 месяцев при текущем канале оплаты |

Окупаемость длинная, поэтому до платного трафика нужны три условия (иначе льём воду в дырявое ведро):

1. **D7 retention ≥ 30 %** на первых 100 органических пользователях;
2. **thinking = 0** и общий httpx-клиент (см. [monetization.md](monetization.md), §6):
   иначе бесплатник стоит втрое дороже, а Pro на потолке лимитов убыточен;
3. **start-метки по источникам**, иначе бюджет нельзя перераспределять между каналами.

## Аналитика (минимум, с первого дня)

Что уже можно считать SQL-запросами к текущей схеме:

- активность и лимиты: `daily_usages` (prompt/RAG/council по дням);
- воронка Trial → Pro: `users.trial_started_at`, `pro_expires_at`, `billing_payments`;
- возврат по уведомлениям: `users.last_daily_checkin_date`, `daily_checkin_streak`;
- глубина диалогов: `conversation_overview`, `conversation_messages_view`.

Чего не хватает:

- [ ] `start`-параметр источника → колонка `acquired_from` в `users`.
- [ ] События «дата рождения указана», «1-й вопрос», «упёрся в лимит», «нажал Trial из лимита».
      Достаточно таблицы событий в Postgres, сторонняя аналитика не нужна.
- [ ] Еженедельный срез: /start по источникам → дата рождения → 1-й вопрос → Trial → D7 → Pro.
